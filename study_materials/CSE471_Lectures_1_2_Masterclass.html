Part 3

🛠 Methodologies Evolution

A methodology is a formalized approach to implementing the SDLC.

Waterfall

Sequential phases. You cannot move to the next phase until the current one is complete.

Pros: Clear requirements, rigorous documentation.
Cons: Inflexible, long time before user sees anything.
Self-test: When should you use Agile vs Waterfall?
Reveal

Use Agile when requirements are unclear or likely to change. Use Waterfall for highly critical, well-understood systems (like aerospace) where upfront rigorous design is required.

Self-test: What is the main advantage of DevOps over traditional deployment?
Reveal

Speed and reliability. It reduces deployment time from weeks/months to minutes/hours while improving system stability through automation and continuous monitoring.

Part 5

⚖️ Feasibility Analysis — The 3 Pillars

Before writing a line of code, we must prove the project is viable. The System Request kicks this off (Project Sponsor, Business Need, Business Requirements, Business Value, Special Issues).

1. Technical
"Can we build it?"
  • Familiarity with application
  • Familiarity with tech stack
  • Project size
  • Compatibility with existing systems
2. Economic
"Should we build it?"
  • Development costs
  • Operating costs
  • Tangible benefits (revenue, savings)
  • Intangible benefits (brand, morale)
3. Organizational
"Will they use it?"
  • Strategic alignment
  • Stakeholder analysis (Champion)
  • Management support
  • User acceptance
⚠️Include/Extend are Use Case concepts, NOT Feasibility types. Feasibility is Tech, Econ, Org.
Self-test: Is "increased brand recognition" a tangible or intangible benefit?
Reveal

Intangible. It cannot be easily measured in exact dollar amounts, unlike "reduced server costs" or "increased sales."

Part 6

💰 The Money Math (Economic Feasibility)

Time is money. A dollar today is worth more than a dollar tomorrow. We use Present Value (PV) to normalize future cash flows.

Present Value (PV)
$$PV = \frac{\text{Cash Flow}}{(1+i)^n}$$
Net Present Value (NPV)
$$NPV = \sum PV_{\text{Benefits}} - \sum PV_{\text{Costs}}$$
Return on Investment (ROI)
$$ROI = \frac{\text{Total Benefits} - \text{Total Costs}}{\text{Total Costs}}$$
Break-Even Point (BEP)
$$BEP = \text{Year} + \frac{\text{Net Cash Flow} - \text{Cumulative NPV}}{\text{Net Cash Flow}}$$

Self-test: If NPV is negative, should we proceed with the project?
Reveal

Usually no. A negative NPV means the project costs more than it earns in present-day dollars. (Unless there are massive overriding intangible benefits like regulatory compliance).

## Financial Formulas ##########################
PV  = CashFlow / (1+i)^n
NPV = Sum(PV_Benefits) - Sum(PV_Costs)
ROI = (Total_Benefits - Total_Costs) / Total_Costs
BEP = Year + ((Net_Cash_Flow - Cum_NPV) / Net_Cash_Flow)
Every successful system balances technical excellence with business value.
